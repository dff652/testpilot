# P0 验收范围与 P1 工作包

P0 交付的是可执行的协议校验、运行时实验和接入清单。P0 通过不表示跨项目 Runner、知识索引或实际业务测试已经实现。

## 已落实的协议边界

- 版本为 `0.1.0`，JSON Schema Draft 2020-12；未知字段/版本拒绝，破坏性变更升级版本并增加迁移样例。
- 首个运行平台为 Linux，运行时实验决定实现语言。首版动作没有动态参数插值和凭据，只允许登记的 typed argv（literal/path）；解释器入口须为相对 path，执行器仍须验证实际路径与登记身份。
- `test` 动作要求计数证据；`check` 动作可不提供测试计数。Schema 和跨字段校验共同执行，不能只用其中一个。
- UTC 时间字段、SHA-256 内容指纹、Git 提交和 dirty 标记都有确定字段。占位样例在 examples 中明确标注 synthetic。
- 结果区分未知数量与零数量；成功必须有产物引用、退出码 0、无缺失产物，测试成功还要求执行数量大于零及一致的统计。
- 知识条目具有所属项目和来源项目，来源、证据和替代引用均携带项目 ID，项目内引用必须一致。reviewed/verified 需要审核身份；verified 还需时间和证据引用。结构合法不能替代审查或证据存在性验证。

## 存储、身份与资源决定

P1 默认将运行证据放在当前 checkout 的 `.testpilot/runs/<run_id>/<attempt_id>/`，索引放在 `.testpilot/index/`，均不进 Git。单个产物上限 10 MiB；达到上限必须记录截断，不可伪装成完整报告。保留期默认 14 天，清理只能显式执行；被已验证知识引用的产物不能按年龄直接删除。保存受限原始文件与可检索脱敏派生文件时分别计算 hash。

备份以来源清单、证据和关系元数据为基础；恢复后核对 hash 和引用，再重建索引。导出/恢复/清理实现及其测试属于 P1/P2，P0 不声明已具备恢复能力。

项目 ID 固定为 `agent-mail`、`ai-asset-hub`、`homelab-doctor`。实际绝对 checkout 路径在本机配置，不提交到可执行清单。每个 checkout 独立登记；识别 Git common-dir 以发现 worktree 的共享资源，不能用目录别名绕过锁。P1 单用户本机采用基于实际资源路径的文件锁，进程退出由 OS 释放；恢复时将未收尾运行标记为 interrupted/runner_error 并检查子进程，不自动重跑。跨机器租约不在 P1。

首批锁范围至少包含 Git common-dir；Go 适配器还需明确缓存和环境是否共享；Shell fixture 的临时目录不能替代整个动作的并发审查。执行前解析路径、拒绝符号链接越界，清理只能指向本次拥有的目录。

索引只读取显式登记的文档白名单，默认拒绝隐藏目录、凭据和运行日志。首次实现仅支持 Markdown 段落/标题和来源定位；变化按内容 hash 重建条目，删除文件立即从当前检索集合移除。只读取实际文件不能证明它属于当前 commit，dirty 文档必须带工作区内容指纹。

P0/P1 不调用模型、不外发资料、不写 AgentMemory。后续模型接入须按项目配置明确数据范围，评测时把答案库与诊断输入隔离。

## 必须验收的场景及当前证据层级

| 场景 | P0 的证据 | 后续实际行为验收 |
| --- | --- | --- |
| 成功、失败、阻断、取消、超时 | 合成结果可校验 | P1 从真实子进程生成结果 |
| 零测试、全部跳过、缺少报告 | 拒绝伪造 passed 的协议样例 | P1 解析器对原生产物核验 |
| 非零退出码、统计矛盾、坏日期 | 合成非法样例被拒绝 | P1 保留原始失败证据 |
| 路径越界、项目串用 | 协议字段与来源关系校验 | P1/P2 文件访问和检索隔离 |
| 超时/取消子进程组 | 独立运行时探针，见 runtime-decision | P1 Runner 异常路径和崩溃恢复 |
| 同资源并发 | 已登记锁需求 | P1 两进程/多 worktree 争锁测试 |
| 脱敏与注入文本 | 固定 argv 边界、无模型 | P1 敏感 fixture、截断和外发限制 |
| 文档增改删与恢复 | 已确定来源与存储规则 | P2 增量索引、删除传播、恢复测试 |
| 三个原生项目对照 | 只读清单；未执行 | 获准范围内采集基线和适配器对照 |

完整契约用例位于 `tests/contract-cases.json`，通过 `make check` 验证。运行时探针单独用 `make probe`，不作为每次文档检查的重复操作。

## 下一阶段任务所有权

以下是拟定代码范围，尚未创建，不是已有模块：

1. 主代理：冻结 schema 和注册接口，负责 `src/testpilot/runner/` 的执行、锁、恢复设计与集成验收。
2. 单个 luna-worker：首先实现 `src/testpilot/adapters/agent_mail.py` 及 `tests/adapters/test_agent_mail.py`，读取原生 SOP JSON，尊重原生排除动作；不得修改 shared schema。
3. 接口经首个适配器验证后，再分配 Go 和 Shell 适配器的独立文件；禁止三个 worker 各自实现进程管理。
4. 另一独立工作包：`src/testpilot/index/` 与相应测试，先验证 fixture 的增改删、中文定位和项目隔离，再接真实文档。

拟定的局部验收命令分别为 `.venv/bin/python -m unittest discover -s tests/runner`、`-s tests/adapters` 和 `-s tests/index`（这些目录在 P1/P2 创建，当前不可作为已执行结果）。每个任务开始前再补齐确切输入样例和允许动作。主代理在整合后的 commit 上核验完整 diff、实际输出、错误路径和未验证项；通过才更新里程碑状态。
