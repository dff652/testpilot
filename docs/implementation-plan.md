# 任务分配与验收

日期：2026-09-09。P0 已完成；P1 的 fixture Runner、登记/锁/恢复与 Agent Mail 首动作已实现并完成隔离对照，见 [P1 验收](p1-runner.md)。Go/Shell 与 P2 尚未实现。当前审查状态见 [审查记录](review-unpushed-2026-09-07.md)，不能把既有检查通过等同于全部问题已关闭。

## 分工原则

主代理拥有需求、共享契约、架构、集成与最终验收。luna-worker 负责输入输出明确的单项目适配器、文档索引或 fixture。共享 schema 定版前不并行实现多个各自定义格式的模块。

每个任务包含：目标、允许修改文件、禁止范围、依赖、验收命令、预期产物和阻断条件。worker 不修改他人文件，不自行提交主代理负责集成的改动，不因“需要通过”放宽断言。

## 里程碑与任务

| 阶段 / 任务 | 负责人建议 | 依赖 | 验收 |
| --- | --- | --- | --- |
| P0 调研与源项目盘点 | luna-worker；主代理复核 | 已有文章和本地证据 | 路径和链接准确，宣传/推断/运行证据分开 |
| P0 契约与技术选型 | 主代理 | 三项目清单 | schema 样例可验证，运行时实验与失败状态明确 |
| P1 fixture Runner | 主代理或单个 worker | 契约冻结 | 参数限制、资源锁、取消/超时、结果持久化及恢复 |
| P1 Agent Mail 适配器 | luna-worker A | Runner 接口 | 包装既有 SOP，不破坏其排除动作和锁语义 |
| P1 AI Asset Hub 适配器 | luna-worker B | Runner 接口 | 保留 Go/race/安装器等动作范围，不把局部通过当全量验收 |
| P1 homelab-doctor 适配器 | luna-worker C | Runner 接口 | fixture 模式，退出码及 OK/WARN/异常语义明确 |
| P2 Markdown 索引 | 单个 worker | 知识契约冻结 | 可追溯引用，增量/删除、中文检索及项目隔离 |
| P2 分析与知识闭环 | 主代理 | 证据与索引 | 假设、验证、修复和回归关联；已审核经验可复用 |
| 各阶段集成验收 | 主代理 | 对应任务完成 | 审查实际改动与原始结果，验证跨模块和跨项目行为 |

A/B/C 是任务角色，不要求同时启动三个 worker。按环境槽位和真实独立性分配，保留主代理做有用的本地工作。第一轮宜从一个适配器开始，验证接口后再扩展。

## 主代理审查清单

- 对照任务目标审查完整 diff，而不只阅读 worker 摘要。
- 检查 schema 漂移、项目身份、路径越界、凭据/日志、资源冲突和状态映射。
- 在最终整合后的版本运行相关检查，记录真实命令、环境、退出码和产物。
- 对 Bug 修复验证缺陷版本失败、修复版本通过；保留测试质量判断，不能只证明代码自洽。
- 抽样对照原生工具与适配器结果；无法执行的真机/外部验收明确标为未验证。
- 归档经审核的知识，更新 DEV_STATE.md，不把假设写成已知事实。

## 并行边界

Agent Mail 同 checkout 的依赖安装会替换 node_modules，不能与依赖该目录的测试并行。TS Platform 的多 worktree 共享资源需要 git-common-dir 等级的锁；原生单轮内部受控并行不等于可以启动多轮外部测试。锁键必须反映真实共享资源，不能简单按 project_id 隔离。

## 首版完成条件

同一入口接入三个原生项目动作；真实结果可对照；异常状态不误报成功；文档来源和运行证据可追溯；项目隔离、更新删除和恢复有测试；至少完成一条 Bug—验证—回归—知识闭环。Web 页面、自动修复次数和生成文本量不作为首版成功指标。

## 审查任务分配

本次使用两个 luna-worker 做只读独立审查：一个负责契约/校验器/样例，一个负责运行时探针/检查流程。主代理复核复现、确认严重度、同步文档并验证文档提交。用户确认后，同两位 worker 按文件所有权完成修复，主代理审查并验证整合版本；R1–R5 已关闭。push 始终由用户手动执行。

P1 本轮分工：主代理实现共享登记、CLI、Runner 与 lifecycle 验收；一位 luna-worker 实现 Agent Mail 适配器及其 fixture，另一位实现独立 CLI 黑盒测试并审查整合边界。主代理承担完整 diff 和最终检查。
