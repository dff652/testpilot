## 技术栈选择应验证什么

本机 Python 3.12.3 和 Node.js v20.19.2 已读到，未安装依赖或升级运行时。Agent Mail 当前机器 Runner 是 Python。先以临时 fixture 比较：调用已有 Runner、取消子进程、解析结果、Markdown 来源定位、跨平台路径。以最小可维护实现为选择标准。

不要以某个模型/API/框架的宣传或旧环境记录确定技术栈。运行时支持版本和依赖锁定在开工时核查；本轮不要求安装 LangChain、向量数据库或 Web 框架。

## 样本和验收集

首批动作逐个复核：Agent Mail 的类型化 SOP 动作、AI Asset Hub 的本地检查、homelab-doctor 的 fixture 检查。复核真实命令并不等于获准立即运行全部测试，尤其安装器、网络和共享数据库动作。

先使用合成 fixture 证明协议。必须覆盖：

1. 正常成功和断言失败，保留原生退出码及报告。
2. 退出 0 但没有测试、全部跳过或缺少报告，不误报 PASS。
3. 不支持环境和缺少依赖，区别于产品缺陷。
4. 超时、取消、子进程遗留、协调器中断和再次启动。
5. 同仓库不同 worktree、同共享资源的锁冲突。
6. 日志中的密钥样本及指令注入文本；不泄露、不执行。
7. 文档新增、修改、移动、删除；不检索到旧版本的当前结论。
8. 两个项目同名文档和相似事故；不串用项目私有知识。

选择历史事故做诊断评测时，隔离修复后提交和答案文档，避免把答案泄漏当成诊断能力。记录原人工流程耗时、建议有效性、人工修改量和模型用量；不预设效率提升百分比。
